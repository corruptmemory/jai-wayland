## Project Overview

Wayland client library for Jai. Bypasses libwayland entirely — speaks the wire protocol directly, uses runtime dlopen for any shared libraries, and generates bindings from Wayland protocol XML specs.

**Current status:** Phases 1-5 complete, plus NVIDIA/hybrid GPU support, plus a Vulkan DMA-BUF presentation path (`hello_vulkan_dmabuf`), plus a runtime-loaded X11/GLX backend (`hello_x11_gl` — for the future vendored window/graphics stack, NOT part of the Wayland path). GL rendering works end-to-end on Mesa (AMD / Intel) and NVIDIA. The primary path is GBM BO-backed: allocate a `gbm_bo`, import it as an `EGLImage` (trying `EGL_NATIVE_PIXMAP_KHR` first, falling back to `EGL_LINUX_DMA_BUF_EXT` for NVIDIA which rejects native pixmap), bind to a GL texture, render to an FBO, export the BO's fd/stride/offset/modifier and hand off to the compositor via `zwp_linux_dmabuf_v1`. The older Mesa `EGL_MESA_image_dma_buf_export` texture-export path is kept as a fallback. Format/modifier selection uses `zwp_linux_dmabuf_feedback_v1` per-surface tranches (filtered through GBM device capability) when available, falling back to the global format list. Validated on a hybrid Intel iGPU + NVIDIA dGPU laptop. Also working: seat-based input API, XKB keysym translation, resizable windows (shm and BO-backed GL), compositor-driven resize with in-flight buffer retirement. **Phase 6 complete: the vendored `Simp`/`Input`/`Window_Creation` stack runs on Wayland via the `Wayland_Support` module (the X11-mirror shared-globals layer + single event pump). Nine upstream-unmodified examples run correctly on Wayland — `invaders` (2D game), `skeletal-animation` (3D depth-tested skinned mesh + GetRect UI), the `GetRect` / `GetRect_LeftHanded` widget showcases, `treemap`, `codex_view`, and the upstream Simp examples `simp_example`, `simp_multiple_windows`, and `simp_render_to_texture` — with full input (keyboard incl. Shift/Caps modifier keysyms + TEXT_INPUT, pointer motion/buttons/wheel, structural touch), selectable triple-buffered Wayland present modes (`fifo`, `mailbox`, `immediate`), compositor-driven resize, multi-window Simp animation/resize/close, and `.QUIT`/Alt+F4/close-button quit. They link **zero display-server/GPU libs** (the linkage thesis) — `libm` + invaders' `libasound` are linked, no `libX11`/`libGL`/`libwayland`.**

**Linkage thesis (the load-bearing invariant): no build-time dependency on the libraries that differ between a Wayland-only and an X11-only box, or that pin a GPU driver** — `libwayland-client`, `libX11`/`libxcb`/`libXau`/`libXdmcp`, and `libGL`/`libGLX`/`libEGL`/`libgbm`/`libvulkan`. These are **all** runtime-`dlopen`'d, so one binary runs on a Wayland-only *or* X11-only box, choosing the backend at runtime. *Universal* libs that exist on essentially every Linux box regardless of display server (`libm`, `libasound`, libstdc++) MAY be linked normally — they don't gate the "drop it on either kind of box" goal. So `ldd build/hello_gl` (pure GL, no image/audio) is `libc` + vdso + ld-linux only; the Simp-based examples link `libm` (and invaders `libasound`) via the **upstream, unmodified** `stb_*`/`Sound_Player` modules, but still **zero** windowing/GPU libs. Verify with `ldd build/{invaders,anim}` → no `libX11`/`libxcb`/`libGL`/`libGLX`/`libEGL`/`libgbm`/`libwayland`. (Earlier this was over-strict "libc only", which forced needless vendoring of `stb_*`/`Sound_Player`; corrected 2026-05-30.)

**Known gaps / next up:** Wayland input niceties — AltGr / level-3 keysyms (keyboard does Shift/Caps levels), `wp_relative_pointer_v1` for edge-crossing mouse-look (pointer currently uses surface-position deltas), touch is structural/untested (no touch device on the dev machine). Clipboard **bitmaps** (`os_clipboard_set_bitmap` is a logged no-op on Wayland; text copy/paste works). Explicit fence sync (the present path still does a coarse `glFinish()`; the default `fifo` mode's bigger frame-callback *block* is gone, and opt-in `mailbox` / `immediate` modes skip the callback gate entirely). Deeper Vulkan examples beyond the triangle DMA-BUF smoke. Fractional scaling. (Phase 6 Wayland backend for vendored Simp/Input/Window_Creation — render + full input (keyboard/pointer/touch) + resize + **drag-and-drop** + **clipboard copy/paste** — is DONE; `invaders` (2D), `skeletal-animation` (3D+UI), the `GetRect` / `GetRect_LeftHanded` showcases, `treemap`, `codex_view`, and the upstream Simp examples run on it. Server-allocated object IDs work — `wl_data_offer` ids ride in events through `unmarshal`'s `*Interface` path. See the "Wayland/X11 backend layer" section.)

## Architecture

**Build metaprogram** (`first.jai`): Creates workspaces for the main build and test suites. Tests auto-run after compilation via `Autorun`.

**XML parser** (`src/xml.jai`):
- Zero-copy pull parser yielding `Xml_Event` values (OPEN_TAG, CLOSE_TAG, ATTRIBUTE, CHARACTER_DATA, COMMENT, PROCESSING_INSTRUCTION)
- `xml_parser_init(doc)` + `xml_next(*parser)` API
- Mode-based state machine: NORMAL → ATTRS → CHARS
- All returned strings are slices into the source buffer (no allocation)
- `xml_decode_entities()` handles `&amp;` `&lt;` `&gt;` `&quot;` `&apos;`

**Protocol model** (`src/protocol.jai`):
- Structs: `Protocol`, `Interface`, `Message`, `Arg`, `Arg_Type`, `Enum_Def`, `Entry`, `Description`
- `parse_protocol(xml_source)` drives the pull parser to build the data model
- Handles hex values (`0x20203843`), destructors, bitfield enums, nullable args, cross-interface enum refs (`wl_shm.format`)
- Validates against all 59 vendored protocol XML files

**Code generator** (`src/generator.jai` + `src/generate_main.jai`):
- Standalone tool reading Protocol structs, emitting Jai source files
- Per-interface files with: doc comments, struct (`id: u32` + `version: u32` with compile-time default), opcodes, enums (regular + bitfield), event tagged unions, request arg structs, typed request functions with `marshal()`/`marshal_constructor()` calls, interface descriptor
- Request functions take `batch: *MessageBuilder` as first param (string builder pattern)
- Naming transforms: `wl_surface` → `Wl_Surface` (type), `WL_SURFACE_ATTACH` (opcode), `wl_surface_attach` (function)
- Handles special cases: untyped `new_id` (polymorphic `$T`), destructors, cross-interface enum refs, numeric identifiers, reserved words
- Deduplicates protocols (core > stable > staging > unstable priority)
- Output: `modules/wayland/` — 56 protocols, 175 interfaces

**Wire protocol** (`modules/wayland/wire.jai`, `connection.jai`, `marshal.jai`):
- `wire.jai` — `inline` primitive writers (`write_u32`, `write_s32`, `read_u32`, `read_s32`), `pack_header`/`unpack_header`, `write_string`/`write_array` with 4-byte padding, `align4`
- `connection.jai` — Three types: `Connection` (socket fd + object ID allocator), `MessageBuilder` (polymorphic outgoing batch buffer), `ReceiveBuffer` (polymorphic incoming buffer). `wayland_connect`/`wayland_disconnect`, `wayland_send(conn, batch)`/`wayland_receive(conn, buf)`/`wayland_send_receive`. `message_queue`/`message_queue_fd` for building messages, `receive_peek_message`/`receive_consume_message`/`receive_pop_fd` for reading.
- `marshal.jai` — compile-time marshal macro using `#expand` + `#insert #run generate_marshal_code(type_info(T))`. Walks request arg struct members at compile time, emits type-specific serialization code. Two paths: fixed-size (stack buffer) and variable-size (runtime computation for strings/arrays). `Fd` args (distinct s32) route to `message_queue_fd` (SCM_RIGHTS out-of-band). Takes `*MessageBuilder` as target. Also `marshal_constructor` for new_id allocation.
- `unmarshal.jai` — compile-time unmarshal macro (mirror of marshal). `unmarshal(*args, payload, recv)` fills a single event args struct; `unmarshal_event(*event, opcode, payload, recv)` dispatches opcode into a tagged union. Walks type_info at compile time, emits type-specific reads. Handles all 8 wire types: u32, s32, Fixed, string, `[] u8`, Fd (via `receive_pop_fd`), `*Interface` (`New(T,, temp)`), `*void`. For tagged unions, walks `tagged_union_bindings` to generate opcode→variant dispatch.

**Generated module** (`modules/wayland/`):
- `module.jai` → `#load` chain → `types.jai`, `wire.jai`, `connection.jai`, `marshal.jai`, `unmarshal.jai`, `shm.jai`, `registry.jai`, `session.jai`, `output.jai`, `input.jai`, `xkb.jai` → per-protocol directories → per-interface files
- `types.jai` — shared types: `Interface_Descriptor`, `Wire_Arg_Type`, `Fixed`, `Fd` (distinct s32), wire constants
- Interface structs: `id: u32` + `version: u32 = #run DESCRIPTOR.version` (no `conn` field, version defaulted)
- Request functions take `batch: *MessageBuilder` as first param, then `self: *Interface`, then protocol args. Use `marshal()` calls that serialize args into the MessageBuilder.
- Constructor functions take `new_id: u32` from caller — no internal allocation, no return value

**GPU policy layer** (`modules/gpu/`):
- `device.jai` — `Gpu_Vendor` enum (INTEL/AMD/NVIDIA/UNKNOWN), `Render_Node_Info` struct. `discover_render_nodes(*nodes)` enumerates `/dev/dri/renderD*` and reads vendor IDs from `/sys/class/drm/renderD*/device/vendor`. `choose_render_node(nodes)` applies selection policy: `JAI_WAYLAND_RENDER_NODE` path override → `JAI_WAYLAND_GPU_VENDOR` name override → first node. `select_render_node()` combines both steps. `print_render_nodes`, `vendor_name`, `vendor_from_id` utilities.
- `dmabuf_bo.jai` — Shared BO allocation and EGLImage import helpers. `create_bo_with_modifier(gbm, w, h, format, modifier, flags)` tries `gbm_bo_create_with_modifiers2` → `gbm_bo_create_with_modifiers` → `gbm_bo_create` in order. `create_image_from_gbm_bo(dpy, bo, ...)` tries `EGL_NATIVE_PIXMAP_KHR` first (Intel fast path), then falls back to `EGL_LINUX_DMA_BUF_EXT` (needed for NVIDIA, which rejects native pixmap with `EGL_BAD_PARAMETER`); returns the DMA-BUF fd when using the DMA-BUF import path so the caller can manage its lifetime separately. `supports_bo_format_modifier(gbm, format, modifier, flags)` checks GBM device capability before committing to a format.

**GPU bindings** (`modules/EGL/`, `modules/gbm/`, `modules/GL/`) — all three follow the same pattern: types + constants + function-pointer variable declarations in one file, `init_X()` loader in another that does `dlopen` + `dlsym`. No `#foreign` anywhere; no build-time linkage.
- `modules/EGL/egl.jai` — includes `EGL_NATIVE_PIXMAP_KHR`, `EGL_GL_TEXTURE_2D_KHR`, the full `EGL_LINUX_DMA_BUF_EXT` import attribute set including `EGL_DMA_BUF_PLANE0_MODIFIER_{LO,HI}_EXT`.
- `modules/gbm/gbm.jai` — includes all BO allocation and query entry points: `gbm_bo_create_with_modifiers`, `gbm_bo_create_with_modifiers2`, `gbm_bo_get_{width,height,stride,stride_for_plane,format,bpp,offset,device,handle,fd,modifier,plane_count,handle_for_plane,fd_for_plane}`, `gbm_device_{is_format_supported,get_format_modifier_plane_count}`. BO usage flags: `GBM_BO_USE_{SCANOUT,CURSOR,RENDERING,WRITE,LINEAR,PROTECTED,FRONT_RENDERING}`.
- `modules/GL/gl.jai` — includes `GLeglImageOES` type and `glEGLImageTargetTexture2DOES` function pointer. `gl_load_egl_image_extensions(get_proc)` is a separate loader pass for the OES EGL image extension (not guaranteed on all contexts — callers should warn and disable BO-backed slots if it returns false). `init_egl_extensions(dpy)` is a separate pass for EGL extensions (must come after `eglInitialize` — extensions are per-display).

**Why vendor GL instead of using Jai's GL module:** Jai's `~/jai/jai/modules/GL/` declares `gl_lib :: #library,system "libGL"` with unconditional `#foreign gl_lib` procedure declarations (even with the `gl_load` function-pointer path available, the foreign decls force link-time resolution). It also `#import "Window_Type"` which on Linux pulls in X11 transitively. Both violate the project's "no external library linkage" thesis. Our vendored replacement loads everything through `eglGetProcAddress` at runtime.

**Vulkan bindings** (`modules/Vulkan/`) — Jai's stock Vulkan module preserved (`module.jai`, `generated_linux.jai`, `loader.jai`), plus `linux_drm_format_modifier.jai` which supplements the headers with the Linux DMA-BUF / DRM-format-modifier extension structs (`VkImageDrmFormatModifierListCreateInfoEXT`, `VkImageDrmFormatModifierExplicitCreateInfoEXT`, `VkMemoryGetFdInfoKHR`, etc.) needed for Vulkan→DMA-BUF export. All Vulkan entry points are loaded at runtime through `loader.jai` — no link-time dependency on `libvulkan`. **Critical design constraint:** the project does NOT use `VK_KHR_wayland_surface`; that extension expects real libwayland-client `wl_display*`/`wl_surface*` proxy pointers, not bare wire-protocol IDs. Vulkan presentation is done via DMA-BUF export wrapped as a Wayland `wl_buffer` — the same final step as the GL path, with Vulkan rendering as the front end.

**X11 bindings** (`modules/X11/`) — Jai's stock `X11/module.jai` vendored *without* the `sofd` file-dialog helper, with Xlib and GLX entry points converted to function-pointer variables loaded by `init_x11()` / `init_glx()`. This module is **not** part of the Wayland wire-protocol implementation — it's a compatibility backend for a future vendored `Window_Creation`/`Simp`/`GetRect` that will pick Wayland or X11 at runtime. `ldd build/x11_smoke` and `ldd build/hello_x11_gl` must show no `libX11`, `libGLX`, `libGL`, or `libxcb`. The X11 module also exports `glx_create_context(window, major, minor)` — ported from upstream `~/jai/jai/modules/GL/GL.jai` so vendored Simp's GLX context creation works without us also vendoring stock GL (which would introduce `#foreign` linkage we don't want). Lives in X11 rather than our GL module because the implementation is pure GLX/X11 windowing glue.

**Upstream vendored modules** (`modules/Window_Creation/`, `modules/Simp/`, `modules/GetRect/`, `modules/GetRect_LeftHanded/`, `modules/Clipboard/`) — Jai distribution modules copied verbatim from `~/jai/jai/modules/` for compatibility with upstream graphical examples. Patch sites: our `modules/X11/module.jai` self-initializes via `init_x11`/`init_glx` in `init_global_display`; `modules/Simp/backend/gl.jai` uses our `gl_load(glXGetProcAddress)` signature instead of stock `gl_load(*gl)`; `modules/Clipboard/Clipboard.jai`'s Linux branch routes the no-arg `os_clipboard_get_text`/`set_text`/`set_bitmap` to `Wayland_Support` under `running_wayland()` (the X11 bodies are untouched). (Image/audio go through the **upstream** `stb_*`/`Sound_Player` modules unmodified — see "Image/audio modules" above.) The `./build.sh - invaders`, `skeletal_animation`, `getrect_example`, `getrect_lh_example`, `treemap`, `codex_view`, `simp_example`, `simp_multiple_windows`, and `simp_render_to_texture` targets build and run upstream example sources against these vendored modules. `first.jai` stages example-local runtime assets into `build/` when the upstream program expects them next to the executable.

**Wayland/X11 backend layer** (Phase 6 — the vendored upstream Simp/Input/Window_Creation stack runs on Wayland, picking the backend by VALUE, not inline `#if`):
- `modules/Wayland_Support.jai` — the GPU-aware support module that sits ABOVE the pure wire `wayland` module and is imported by NAME from the windowing consumers (Simp, Input, Window_Creation). It is the Wayland analogue of `modules/X11`: a bag of well-known module-scope globals + the functions over them. Because Jai instantiates an imported module once and name-based `#import` dedups across importers, the globals here are ONE shared instance — the `x_global_windows`/`x_global_display` pattern. Owns: the shared EGL/GBM/GL context (matching Simp's process-global GL objects), the `wayland_global_windows` registry (`Wayland_Window` = identity + per-window BO slots + dmabuf format/modifier + present-mode state (`fifo` / `mailbox` / `immediate`) + optional `tearing-control-v1` object + `size_dirty` / close state), the per-window GL ops (`wl_window_init_gl` / `wl_make_current` / `wl_window_resize_gl` / `wl_present_and_pace`), the format/slot helpers, the acquired keyboard/pointer + parsed keymap + `provisional_input_events`, and the SINGLE event pump `wl_pump` that drains the one compositor connection and routes every message — render (frame callback / buffer release / configure / close) by registry object-id, input decoded into stable `Wl_Input_Event`s. `JAI_WAYLAND_PRESENT_MODE=fifo|mailbox|immediate` selects the Simp Wayland policy: `fifo` is the default bounded previous-frame-callback throttle; `mailbox` and `immediate` skip that callback wait, rely on buffer-release backpressure while keeping one free render slot, and drop frames instead of callback-pacing the app loop; `immediate` also requests `tearing-control-v1` async presentation when advertised. Low-latency modes must actively call `wl_pump_timed(0)` from swap/input because FIFO's blocking frame-callback receive is absent; `wl_pump(false)` only drains already-buffered messages and can starve pings, input, and buffer releases. On the `pacing-experiments` branch, mailbox/immediate also apply a tiny active-resize sleep while compositor configure events are streaming; `JAI_WAYLAND_TRACE_RESIZE=1` logs the configure/resize/pacing path. In FIFO mode, `wl_present_and_pace` returns to the app when configure/close arrives while waiting on an older frame callback, which keeps Hyprland multi-window resize/close/animation from stalling; the wait is also **bounded** (`PRESENT_PACE_TIMEOUT_MS`, 50 ms) so an occluded window (a hidden tab in a Hyprland group / another workspace), which the compositor sends no frame callbacks to, gets flagged `wl_pacing_starved` and skipped rather than stalling the single-threaded render loop — a visible sibling keeps full vsync pacing, and an all-occluded app keeps the timeout so the loop idles. `running_wayland()` + `Display_Manager` live here too. EGL/gbm/gpu/GL deps live ONLY in this module, so the pure `wayland` wire module + minimal consumers (hello_globals, tests) stay GPU-free; ldd stays free of windowing/GPU libs regardless (all dlopen'd).
- **Backend selection is a value, not a dispatch pointer.** `WS.Display_Manager` on Simp's `Backend_Platform_Specific`, detected once in `CheckInit` via `running_wayland()`, branched inline at the 4 backend op sites in `gl.jai` (X11 fns in `backend/x11_dispatch.jai` vs Wayland glue in `backend/wayland_dispatch.jai`). This REPLACED the earlier `context.simp_dispatch` function-pointer indirection — `dispatch.jai` (`Simp_Op_Args` union), `wayland_gl.jai`, and `Window_Creation/linux_init.jai` were all deleted.
- `modules/Window_Type.jai` — Linux branch is a tagged union (`.X11 ,, x11: X11.Window` / `.Wayland ,, wayland: Wayland_Window_State`). `Wayland_Window_State` is a bare `{ surface: u32 }` — a copy-safe GPU-free identity handle (the wl_surface id) that resolves to the full registry record via `WS.find_wayland_window(surface)`. The richer per-window state lives in the WS registry, and the EGL/GBM context is shared module-wide in WS, NOT here. `operator ==` overloads re-exported through `Window_Creation/module.jai`.
- `modules/Window_Creation/linux.jai` — `create_window` picks the Wayland vs X11 arm via `WS.running_wayland()`; the Wayland arm `create_window_wayland` builds the surface stack, waits for the first configure, and `array_add`s a `Wayland_Window` into `WS.wayland_global_windows` (the X11 `array_add(*x_global_windows, win)` mirror). While waiting for a new window's first configure, it routes configure/close events for already-registered windows through `Wayland_Support` so multi-window startup does not drop resize state. `get_dimensions` has a Wayland branch (registry size; Wayland clients have no on-screen position).
- `modules/Simp/backend/{x11_dispatch,wayland_dispatch}.jai` — per-op backend functions (`x11_backend_init` / `wl_swap_buffers` / …) called from `gl.jai`'s `display_manager` branch. `wayland_dispatch.jai` is thin glue: find the registry record, call the WS op, do Simp's FBO bind. Present is vertically flipped via `wl_surface.set_buffer_transform(FLIPPED_180)` (GL FBO is bottom-up vs the top-down dma-buf).
- `modules/Input/{x11,wayland}.jai` — `update_window_events` (x11.jai) branches on `running_wayland()` to `update_wayland_window_events` (wayland.jai), which drains `WS.provisional_input_events` (decoded by the pump) into Input's model, reusing x11.jai's `get_key_code` (xkb keysyms share X11 keysym numbering). The X11 arm maps `MotionNotify` into `mouse_delta_x/y` with enter/leave baselining, which keeps XWayland skeletal-animation camera rotation working. Full Wayland input surface: **keyboard** — modifier-aware keysyms (Shift/Caps xkb level selection, with a level-0 fallback so one-level keys like Shift/F-keys still resolve when the modifiers event precedes the key event; named-key `symbols[N]` forms are parsed so physical Alt+F4 works under Hyprland) + TEXT_INPUT events for printable chars (suppressed under Ctrl/Alt/Meta, so command chords like Ctrl+C/V/X don't insert a literal char into a text field) + client-synthesized **autorepeat** (Wayland delivers no repeat events; `Wayland_Support` replays the held key per the compositor's `wl_keyboard.repeat_info` rate/delay, flagged `Event.repeat`); **pointer** — motion→`mouse_delta`, buttons→`input_button_states` (evdev→`Key_Code`), wheel→`MOUSE_WHEEL`+`mouse_delta_z`, enter/leave→`input_application_has_focus`; **touch** — structural (`Event.TOUCH` + `touch_pointers`; untested, no touch device on the dev machine); **drag-and-drop** — the pump decodes `wl_data_device` drops into a `DRAG_DROP` stable event, which `wayland.jai` parses (`text/uri-list`, `file://` stripped) into `Event.DRAG_AND_DROP_FILES` (X11 parity; verified with a PCManFM-Qt drop); **clipboard** — the same `wl_data_device` carries selection events; `Wayland_Support.wl_clipboard_get_text`/`set_text` (backing the vendored `Clipboard` module) read the current selection offer / own one via a `wl_data_source`, so GetRect's text-input Ctrl+C/V works. **Client API** (`modules/wayland/registry.jai`, `session.jai`, `shm.jai`, `dmabuf.jai`):
- `session.jai` — `WaylandSession` struct (Connection, ReceiveBuffer, globals, bound objects). Lives in `#add_context wayland_session: *WaylandSession;`. `init_wayland_session()` connects, discovers globals, binds compositor/wm_base. `for_expansion` on `*WaylandSession` iterates incoming messages, handles ping/pong and `wl_display.error` transparently (uses `defer` for message consume so `continue` is safe in loop bodies), yields `WaylandMessageHeader`, exposes `recv: *ReceiveBuffer` via backtick binding (for `unmarshal` Fd support). Context-based convenience overloads: `allocate_id()`, `wayland_send(*batch, drain=)`, `session()`, `connection()`, `registry()`, `compositor()`, `wm_base()`, `globals()`.
- `registry.jai` — `discover_globals(conn)` performs get_registry + sync roundtrip using MessageBuilder/ReceiveBuffer, returns `[] Global_Info` + registry ID. Context-based overload stores into session. `find_global(globals, name)` / `find_global(name)` lookups. `init_display(conn)` creates wl_display proxy (always ID 1).
- `shm.jai` — `memfd_create(name, flags)` thin wrapper over Linux syscall for anonymous shared memory.
- `output.jai` — `Mode_Info`, `Screen_Info` structs, `get_screens_info()` discovers all compositor outputs via wl_output bind + sync roundtrip + `unmarshal_event`. Returns `[] Screen_Info` with name, modes, current_mode, scale_factor, geometry.
- `input.jai` — Seat-based input discovery. `Seat_Info` (seat, name, capabilities), `Keyboard_Info` (seat_index, keyboard, keymap_fd, keymap_size), `Pointer_Info` (seat_index, pointer). `get_seats_info()` enumerates seats and their capabilities. `get_keyboards_info(seats)` / `get_pointers_info(seats)` acquire wl_keyboard / wl_pointer for seats advertising the respective capability; keyboards receive the keymap event during acquisition. `get_keyboard_event(header, keyboards, recv)` / `get_pointer_event(header, pointers, recv)` match an incoming message against the known input objects and unmarshal the appropriate event tagged union — for clean event loops that route messages by object ID.
- `xkb.jai` — XKB keymap parser. `parse_keymap_fd(fd, size)` mmaps the compositor's keymap fd and parses the xkb text format into a `Keymap` (`[768] Keymap_Entry`, each entry holds up to 4 keysyms per level). Two-phase parse: `xkb_keycodes` section maps xkb names (`AD01`, `AE02`, `FK04`) to xkb numbers, then `xkb_symbols` section maps names to hex or named keysyms. Handles compact `[ 0x71, 0x51 ]` entries and xkbcommon-style `symbols[1]= [ F4, ... ]` group entries; the result is keyed by evdev keycode (xkb_number - 8). `keymap_get_keysym(keymap, evdev_keycode, level)` looks up a keysym at shift level 0 or 1. `keysym_is_ascii(keysym)` flags printable-ASCII keysyms. This replaces hardcoded evdev scancodes with layout-independent keysym handling.
- `dmabuf.jai` — zwp_linux_dmabuf_v1 discovery and feedback helper. `Format_Modifier`, `Dmabuf_Info` structs. `get_dmabuf_info()` binds the dmabuf global, does a sync roundtrip, collects all (format, modifier) pairs the compositor advertises via `.modifier` (v3+) or legacy `.format` events; sets `feedback_supported = true` if protocol version ≥ 4. `pick_format(info, preferred_fourcc)` picks a pair preferring `DRM_FORMAT_MOD_LINEAR` > `DRM_FORMAT_MOD_INVALID` > any tiled. `Dmabuf_Feedback_Tranche`, `Dmabuf_Feedback_Info` structs for v4+ feedback. `get_default_dmabuf_feedback(dmabuf)` / `get_surface_dmabuf_feedback(dmabuf, surface)` request and collect a `zwp_linux_dmabuf_feedback_v1` snapshot: mmaps the format-table fd (16-byte entries: u32 format + u32 padding + u64 modifier), walks tranche events (`TRANCHE_TARGET_DEVICE`, `TRANCHE_FORMATS` index list, `TRANCHE_FLAGS`, `TRANCHE_DONE`, `DONE`). `pick_format_from_feedback(feedback, fourcc)` returns the first matching entry in compositor tranche order. Modifier constants `DRM_FORMAT_MOD_LINEAR` (0) and `DRM_FORMAT_MOD_INVALID` (`0x00ffffffffffffff`) are exported.
- `type_registry.jai` — Generator-emitted compile-time map from `*Type_Info` → `(interface_name: string, version: u32)`. Lets bind/registry code do reflective lookups (e.g. `wl_registry.bind` needs the interface name as a wire string). Bridges Jai's compile-time type identity with Wayland's stringly-typed interface registry. Auto-generated — do not edit.
- **Design: no inversion of control.** Application owns the event loop via `for session() { ... }`, switches on object IDs, decodes events with `unmarshal`/`unmarshal_event` or inline `read_u32`/`read_string`. No callbacks, no dispatch tables, no event queues.
- **Message-shaped API:** Requests are batched into a `MessageBuilder` (string builder pattern), sent explicitly with `wayland_send`. No hidden flush state.
- Wire read helpers: `read_string(src) -> string, u32` and `read_array(src) -> [] u8, u32` — mirrors of write_string/write_array.

## Key Patterns

- No external dependencies — only Jai standard library (Basic, File, String, File_Utilities, Compiler, Autorun, Socket, POSIX)
- Zero-copy throughout: XML parser returns slices into the source buffer, protocol parser stores those slices
- Test pattern: named procedures with `assert()` + `print("  PASS: ...\n")`, called from `main()` in groups
- `first.jai` uses `build_and_run_test()` helper with `Autorun.run_build_result_of_workspace()` for test execution
- Generator returns temp-allocated strings via `String_Builder.{ allocator = temp }`; file writer uses `write_entire_file(path, *sb)` which accepts `*String_Builder` directly
- Compile-time code generation: `marshal`/`unmarshal` macros use `#expand` + `#insert #run` to walk struct type_info and emit serialization/deserialization code. `unmarshal_event` walks `tagged_union_bindings` for opcode dispatch. Debug expansions in `.build/.added_strings_wN.jai`
- **Client ID wire ordering:** Wayland compositors expect client-allocated IDs in monotonically increasing order on the wire. Always call `allocate_id()` immediately before queuing the message that creates that object. Pre-allocating IDs and sending in different order causes `wl_display.error`.
- **Client IDs must be contiguous — no gaps (implicit spec quirk):** The Wayland spec allows any ID in [1, 0xFEFFFFFF] as long as it's not already in use, but Hyprland (wlroots) and other compositors in practice enforce strict contiguity: if the last `new_id` the compositor saw was N, the next must be N+1. Any gap causes `WL_DISPLAY_ERROR_INVALID_METHOD`. This means you cannot pre-reserve a range by advancing `conn.next_id` without sending messages for those IDs. Use `Id_Cache` for recycling short-lived objects: first allocation is always sequential, and later allocations reuse cached IDs only after `cache_free` marks the prior object dead following its destructor event.
- **`defer` in for_expansion:** The `for session()` for_expansion uses `defer` for `receive_consume_message` so that `continue` in loop bodies doesn't skip message consumption. Never put post-body cleanup after `#insert body` without `defer` — `continue` will skip it.
- **Dogfood the convenience API:** Code inside the wayland module (output.jai, input.jai) should use session.jai convenience functions (`globals()`, `registry()`, `allocate_id()`, `for session()`, `wayland_send(*batch)`) rather than reaching into `context.wayland_session` directly.
- **Opcodes are per-interface, not global.** Every Wayland interface restarts opcode numbering at 0. `wl_buffer.release`, `wl_callback.done`, `wl_output.geometry`, `wl_seat.capabilities`, `wl_keyboard.keymap`, and `wl_surface.enter` are *all* opcode 0 on the wire. Generated constants like `WL_BUFFER_RELEASE` and `WL_CALLBACK_DONE` both literally equal 0. When routing incoming messages in a `for session()` loop, match on `(object_id, opcode)` — matching on opcode alone silently catches events from other interfaces and swallows them. This bit the first GL render loop before we disambiguated.
- **Jai operator precedence: `cast` binds looser than `<<`.** `cast(u32) b << 8` parses as `cast(u32) (b << 8)` — the shift happens on `u8` first and overflows. For fourcc packing and similar bit-assembly, wrap each cast+shift in explicit parens: `((cast(u32) b) << 8)`. The `gbm_fourcc` helper in `modules/gbm/gbm.jai` has an in-code comment warning about this — copy the pattern.
- **`VK_KHR_wayland_surface` is unusable here.** That extension expects real libwayland-client `wl_display*` and `wl_surface*` proxy pointers, not bare wire-protocol object IDs. The project therefore never uses Vulkan WSI; Vulkan presentation goes through DMA-BUF export wrapped as a `wl_buffer`. This is a permanent design constraint, not a TODO.
- **`Id_Cache` for short-lived object IDs.** Replaces the earlier `Reuse_Block` design. First allocation is always sequential (preserves contiguous-ID invariant); subsequent allocations reuse a cached ID only after `cache_free` marks the prior object dead following its destructor event. Used for frame callback IDs in `hello_gl`/`hello_vulkan_dmabuf`.
- **Modules log, they don't print.** Code inside `modules/` uses Jai's standard `log` facility (`log("...")`, `log_error("...")`) rather than raw `print`. Examples still use `print` for direct user-facing output. Don't reintroduce `print` calls inside module files.

## Wire Protocol Design

**Compile-time marshalling:** The `marshal(batch, object_id, opcode, args)` macro walks request arg struct fields via `type_info` at compile time and emits type-specific byte-packing code into the MessageBuilder. `#inline` primitive writers ensure zero-overhead — the optimizer sees only raw stores. This is the "Lisp-like macro" pattern from `csv_write_row` in jai-http.

**Type-to-wire mapping (all 4-byte aligned, native-endian):**
- `u32`/`s32` → 4 bytes direct
- `Fixed` → 4 bytes (write `.raw` as s32)
- `string` → u32 length (incl NUL) + data + NUL + pad to 4
- `[] u8` (array) → u32 length + data + pad to 4
- `*Interface` (object) → 4 bytes (write `.id`)
- `Fd` (`#type,distinct s32`) → NOT on wire, passed via SCM_RIGHTS out-of-band

**Message header:** 8 bytes — `[object_id: u32][(size << 16) | opcode: u32]`

## Generator Special Cases

These edge cases were discovered during the compilation smoke test against all 59 protocol XMLs:

- **Numeric identifiers:** `wl_output.transform` has entries `90`, `180`, `270` — prefixed with `_` since bare numbers aren't valid Jai identifiers
- **Reserved words as field names:** Some protocol args use Jai reserved words (e.g., `context`) — suffixed with `_`
- **Self-referencing #load:** Some protocols have an interface with the same name as the protocol (e.g., `ext_image_capture_source_v1`) — interface filename gets `_interface` suffix to avoid the loader `#load`-ing itself
- **Protocol deduplication:** Stable/staging versions supersede unstable versions (e.g., `xdg_shell` vs `xdg_shell_unstable_v5`). Generator sorts by priority (core > stable > staging > unstable) and skips protocols whose interface names collide. 3 unstable protocols are skipped.
- **Tagged union constraint:** Jai's `.TAG ,, field` syntax supports only one field per variant. Multi-arg events use wrapper structs (e.g., `Wl_Pointer_Motion_Args`). Zero-arg events use empty structs.

## Next Steps

1. **Explicit fence sync** — the present path still does a coarse `glFinish()` before DMA-BUF export (~0.68 ms/frame); replacing it with fences (`EGL_KHR_fence_sync` + `wp_linux_drm_syncobj_v1`) would release the CPU sooner. `Gl_Slot.acquire_fence_fd` / `.release_fence_fd` are placeholder fields ready for this. **The bigger present-path cost — the synchronous frame-callback block — is now REMOVED** (`docs/plans/2026-05-31-wayland-async-present.md`, DONE 2026-05-31). Per-frame swap profiling (getrect_example @ 2552×1387, both backends) found the old present cost ~4 ms/frame (glFinish 0.68 ms + a synchronous block on the frame callback 3.3 ms), so `wl_present_and_pace` first became an **asynchronous, vsync-paced FIFO present**: triple-buffered (`SIMP_WL_SLOT_COUNT` 2→3), throttling on the PREVIOUS frame's callback rather than this one — a CPU-bound app finds it already fired (no wait, no latency), a fast app caps to vsync (no uncapped GPU burn, the way GLX's triple-buffered swap behaves). That dropped FIFO present overhead from ~3.3 ms to ~20 µs for CPU-bound GetRect (matching XWayland) while keeping fast `hello_simp` vsync-capped. `JAI_WAYLAND_PRESENT_MODE=mailbox|immediate` now opts out of callback pacing entirely and uses buffer-release backpressure; `immediate` also requests `tearing-control-v1` async when advertised. `glFinish`→fence is the small remaining ~0.68 ms. **The real frame-rate ceiling is unchanged:** ~28.5 ms/frame of **backend-agnostic** GetRect + Simp CPU work (immediate-mode UI rebuild + draw-call submission) — *identical* on X11 (`cpu/other` 28.4 ms) and Wayland (29.5 ms) — caps both backends at ~30–34 fps unless the app/example itself gets optimized. Cutting the 28.5 ms (prime suspects: CPU-rasterized color wheel, per-frame geometry rebuild, draw-call count) is upstream/vendored, a larger dig that needs a profiling pass before touching anything.
2. **Low-latency resize pacing experiment** — keep iterating on `pacing-experiments` after more Hyprland/GetRect resize data. The current 4 ms active-resize sleep is intentionally conservative and should be tuned or removed based on measurements. The next promising direction is bucketed GPU slot capacity: split logical window size from BO/EGLImage/GL texture/FBO/wl_buffer allocation size, grow slots in buckets, and only recreate when logical size exceeds capacity. Use `glViewport`/`glScissor` for the logical render region and `wp_viewporter` source/destination state for presentation cropping. `wl_surface.damage_buffer` is not a crop; oversized attached buffers otherwise change the compositor-visible surface size. 9. **Tiling-WM floating-widget sizing (documented curiosity; fix gated, default-off).** Under a tiling WM that force-resizes a window away from its requested size (Hyprland tiling a 1920×1080 request → 2552×1387), GetRect's floating sub-windows bake ~1.28× larger on our Wayland backend than on XWayland/Windows/macOS. **Root cause:** GetRect bakes each sub-window's rect ONCE (`if !subwindows_initted`, size `= 0.4×window_height` etc.) from the example's `window_height` variable; that variable starts at the *requested* size and is corrected by a resize event. xdg-shell forces `create_window_wayland` to learn the compositor's forced size *synchronously* (wait-for-configure-before-map), so the app sees it on frame 1 *before* the bake; X11/Win/macOS deliver the forced size as an *async* event *after* the first bake, so they bake at the requested size. Per-frame UI (title, background, left-side widgets) is identical across all backends — only the once-baked floating windows diverge, and GetRect's own `rescale` can't compensate (it keys off render-target *changes*, which don't happen here — the render target is the forced size throughout). **NOT a GL/scale/DPI bug:** it disappears entirely if the window opens at its requested size (any floating/stacking WM — verified by launching `getrect_example` floating at 1920×1080; the layout is pixel-correct). **Planned fix (gated):** defer the first Wayland resize event by one frame (a per-window "first `update_window_events` seen" latch in the `size_dirty → Window_Resize_Record` path), so the bake uses the requested size — faithful parity with the reference platforms, not out-cleverness. Gate behind `JAI_WAYLAND_ENABLE_TM_QUIRKS` (proposed `ENABLE_TM_QUIRKS`; the project's other runtime knobs carry the `JAI_WAYLAND_*` prefix), **default OFF** — most users run floating/stacking WMs where the issue can't arise and the current behavior is correct-for-the-window. Before implementing, instrument `window_height` + `render_target` for the first few frames on both backends to reproduce the reference ordering exactly.
